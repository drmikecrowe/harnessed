# Classified surviving mutants for #456 -- mutation layer, tools/gauntlet-456.sh.
#
# An entry here is a CLAIM, not a mute: "this mutant survives, and here is why no behaviour turns
# on it." The gate enforces the file in BOTH directions -- an unlisted survivor fails the layer, and
# so does a listed mutant that no longer survives. The second half is what stops this file rotting
# into a blanket excuse: once a mutant becomes killable, the entry must go.
#
# THE ONE CLASS LISTED HERE: mutmut's string mutations (`"x"` -> `"XXxXX"`, and case inversion)
# applied to the TEXT of error messages. Killing these means asserting user-facing prose
# character-for-character, which is brittle and is what anti-gaming rule 4 warns against. Before
# classifying, the rule is to name the real defect that could live in the same expression: for a
# message literal there is none -- no branch, no comparison, no argument to another call reads it.
#
# What IS asserted about these messages, so the classification is narrow rather than a blanket pass:
#   * guard_ownership   -- names the path, the cause ("rootless"), the uid, "subuid", and BOTH
#                          remediations ("rootful", "podman"); the unreadable-daemon variant names
#                          "docker info"; the podman message names the pinned mapping, bare.
#   * _preflight_runtime-- names the cause, the uid, "subuid", both remediations, and exits 1.
#   * _runtime          -- names "neither podman nor docker", and exits 1.
# Mutants that changed EXIT CODES or COMMAND ARGV were fixed with tests, never listed here.


#
# Regenerate: python3 tools/regen-allowlist-456.py <mutmut-run-log>
